# SentiIME 架構說明

## 1. 設計目標

- **輸入引擎與 UI 完全分離**：引擎只接受抽象按鍵 `KeyEvent`，回傳 `KeyOutcome`，
  任何前端（egui GUI、CLI、未來的系統 IME 框架）都只是薄殼。
- **Ports and Adapters（六角形架構）**：領域核心定義介面（Port），具體實作（Adapter）
  在外層，可替換、可單獨測試。
- **可追查**：候選可顯示來源與排序分數；目前同時使用統計、規則與神經模型，分數不等於完整語意解釋。

## 2. Crate 依賴圖

```
                     ┌──────────────┐
                     │  senti-core  │  領域模型 + Ports（無任何內部依賴）
                     └──────┬───────┘
      ┌──────────────┬──────┴───────┬───────────────┬───────────────┐
      ▼              ▼              ▼               ▼               ▼
senti-context  senti-predictors senti-plugins  senti-storage   senti-engine
(Adapter)      (Adapter)        (Adapter)      (Adapter)       (Application core)
      └──────────────┴──────┬───────┴───────────────┴───────────────┘
                            ▼
                     ┌──────────────┐
                     │  senti-app   │  Composition Root + Session + senti-cli
                     └──────┬───────┘
                            ▼
                     ┌──────────────┐
                     │  senti-gui   │  egui Demo
                     └──────────────┘
```

**關鍵規則**：`senti-engine` 只依賴 `senti-core`，不認識任何 Adapter。
所有 Adapter 只在 `senti-app::build_engine` 這個組裝點被組合。

## 3. Ports（`senti-core`）

| Port | 職責 | 預設 Adapter |
|---|---|---|
| `Predictor` | 依目前組字產生候選詞（純函式，不持有可變狀態） | `PinyinPredictor`、`EnglishPredictor`、`UserHistoryPredictor`、`AssociationPredictor` |
| `Plugin` | 可啟停擴充：`suggest`（排序前加入候選）、`refine`（排序後調整） | `EmojiPlugin`、`DateTimePlugin`、`CalculatorPlugin` |
| `ContextAnalyzer` | 原始環境訊號 → `InputContext` | `RuleBasedContextAnalyzer` |
| `UserModelStore` | 載入／儲存個人化模型 | `JsonFileStore`、`InMemoryStore` |
| `Clock` | 本地時間（可注入，測試可凍結） | `SystemClock`、`FixedClock` |

個人化資料 `UserModel` 透過 `PredictionQuery` 以唯讀借用傳給 Predictor，
因此 Predictor 本身無狀態，替換或並行測試都很容易；學習只發生在引擎一處。

## 4. 引擎內部（`senti-engine`）

| 模組 | 職責 |
|---|---|
| `engine.rs` | 組字狀態機、選字／上屏、學習、候選管線、對外查詢 API |
| `composition.rs` | 原始按鍵 + 已部分選定的詞（支援「你好|shijie」分段選字、退格復原） |
| `ranking.rs` | `ContextualRanker`：情境標籤、個人詞頻、接續詞頻三種加權 |
| `plugin_registry.rs` | 插件註冊、啟停、列表 |
| `punctuation.rs` | 中文模式全形標點 |
| `builder.rs` | `EngineBuilder`，每個 Port 都有安全預設，方便測試只注入需要的部分 |
| `view.rs` | `EngineView`：提供給 UI 的唯讀快照（預編輯、分頁候選、情境） |

### 候選管線

```
PredictionQuery ─► 所有 Predictor.predict ─┐
                  啟用中 Plugin.suggest ───┴► 去重 ─► ContextualRanker ─► Plugin.refine ─► 去重 ─► 原始字母保底 ─► 分頁
```

### 排序公式

```
final = base（Predictor 給的分數）
      + w_context  × Σ tag_affinity(tag, context)     // formal/casual/positive/negative/morning/evening/tech/work
      + w_personal × ln(1 + 使用者對此編碼選此詞次數)
      + w_bigram   × ln(1 + 此詞接在上一個上屏詞之後的次數)
```
權重在 `RankingWeights`（預設 0.2 / 0.35 / 0.25）。

### 學習

- 每次**完整轉換**上屏時記錄 `(編碼, 詞)`；多次分段選字組成的片語整體也會被學成一個詞
  （例如 `nihaoshijie → 你好世界`），下次直接成為首選。
- 記錄上一詞 → 本詞的接續關係，供聯想與排序使用。
- 插件產生的內容（日期、計算結果）與原始字母上屏**不學習**。
- 使用者資料載入失敗時，引擎以空模型執行並**停用寫入**，避免覆蓋損壞但可能可救回的檔案。

## 5. 情境感知（`senti-context`）

- **情緒**：中英文關鍵詞，處理否定（「不開心」「不太開心」「not happy」），英文需整詞比對。
- **正式程度**：應用程式先驗（郵件偏正式、聊天偏輕鬆）+ 正式／輕鬆標記詞。
- **時段**：早上／下午／晚上／深夜。
- 只分析游標前最後 80 個字元，讓情境跟隨使用者「現在」正在寫的內容。

## 6. 擴充方式

- **新增預測器**：實作 `Predictor`，在 `senti-app::build_engine` 註冊。
- **新增插件**：實作 `Plugin`（只需 `manifest`，`suggest`／`refine` 皆有預設），
  加入 `senti_plugins::builtin_plugins` 或在組裝點 `.plugin(...)`。
- **換成統計／神經網路模型**：實作 `ContextAnalyzer` 或 `Predictor` 即可，引擎不需修改。
- **換儲存**：實作 `UserModelStore`（如 SQLite）。

## 7. 測試策略

| 層級 | 位置 | 內容 |
|---|---|---|
| 單元測試 | 各 crate `#[cfg(test)]` | 音節切分、詞庫解析、排序、情緒、插件、儲存 |
| 引擎行為測試 | `senti-engine/tests/state_machine.rs` | 只用 stub Port 驗證狀態機、分頁、學習、插件啟停、損壞資料保護 |
| 端對端測試 | `senti-app/tests/end_to_end.rs` | 真實詞庫 + 凍結時鐘：整句轉換、情境排序、學習持久化 |

## 8. 台灣標準注音

應用程式保留 `InputMode::Zhuyin` 純注音；`InputMode::Chinese` 保留為拼音，
舊 JSON 的 `Chinese` 鍵與既有拼音編碼保持可讀。注音使用獨立的 `Zhuyin` 學習分區，
保留聲調與空白一聲邊界；接續詞仍以中文字詞共用。

`senti_core::zhuyin` 提供 37 個標準鍵位、五聲及音節解析。組字儲存 ASCII 鍵碼，
`Candidate.consumed` 仍是原始鍵碼的位元組位置；只有 `EngineView.preedit` 與候選註解
轉為注音符號（輕聲顯示於音節前）。因此引擎原有的分段選字與退格復原不需處理注音 UTF-8 切片。

`ZhuyinPredictor` 合併種子與擴充的帶聲調 TSV，支援末音節前綴及詞頻 Viterbi 整句轉換。
擴充資料與拼音詞庫提供80,104 個不重複多字詞語／片語；讀音異體不重複計數。
載入時驗證聲調、字／音節數、正值詞頻與標籤，並依 `(編碼, 文字)` 去重。
首音節鍵碼前綴索引同時用於候選與 Viterbi 查詢，避免每個按鍵、每個句子位置全表掃描。
有聲調的音節必須精確匹配；聲調鍵結束音節，之後直接輸入下一音節。
資料來源、授權與重建指令見 `crates/senti-predictors/data/SOURCES.md`。

注音數字鍵優先輸入注音／聲調，`OpenCandidates`（GUI 的 ↓）切入選字狀態，
才啟用數字選字。`CandidateNext`／`CandidatePrevious` 移動頁內游標；
`EngineView.selecting`、`candidate_cursor` 供前端顯示。Esc 先離開選字，再取消組字。
Enter 在組字時完成整句，在選字時接受游標候選；無法完整轉換時保留組字，不會部分上屏。

切換進出注音模式會取消未確認組字；拼音與英文互切保留原有上屏行為。
引擎記住上次中文方案，Shift／Tab 的中英切換會回到該方案。
日期／計算機仍使用原有拼音／英文快捷碼，不攔截注音鍵。

GUI 保留 egui，預設跟隨系統主題，可在本次執行中切換淺／深色。
主輸入區與候選列置中，設定預設收合，進階功能按需展開。

### 輸入事件與文件編輯

GUI 保留原生事件順序，在每個事件送出前才依引擎最新狀態解析方向鍵，
避免同一畫面更新中的連按 ↓ 或中英切換使用過期模式。Shift 單擊依
`ModifiersChanged` 事件判斷；其他按鍵、快捷鍵及失去焦點都會使未完成的 Shift 單擊失效。

`InputEngine::cancel_composition` 同時清除組字、選字與聯想狀態。
`Session::set_document` 用於整份替換／清空文件，會先取消組字；
`set_surrounding_text` 仍只同步環境，不改動組字。
`Session::paste_text` 插入剪貼簿原文，不將剪貼簿內容當成輸入法選字學習；
已有組字時先以 Enter 嘗試完成，若無法轉換便保留目前顯示的預編輯文字。
空字串貼上不改變狀態。

連按聲調鍵只替換最後一個未轉換音節的聲調，不復原已選字詞。
無效的候選數字保持選字狀態，避免接下來的數字意外變成注音鍵。

### 詞庫擴充驗證

`scripts/import_mcbopomofo.py` 從已保留的高頻子集離線產生兩種輸入方案的擴充資料，
並更新 `lexicon_manifest.json` 的來源雜湊與去重統計；`--check` 只核對、不寫入。
完整上游重新匯入需使用固定版本與已記錄的 SHA-256。
測試除檢查詞庫規模，亦逐筆驗證所有注音多字詞與新增拼音多字詞可在一般候選上限內找到，
並比較索引查詢與全表掃描結果，確保效能調整不改變匹配規則。

## 9. 中英混打

應用程式預設 `InputMode::Mixed`，底層引擎 Builder 的原有預設不變。
混打的組字保留原始鍵碼，完成音節後呈現中文；`EngineView.phonetic_preview` 僅在選字時提供注音解讀；
純注音仍使用原本的注音預編輯顯示。

混打分別以 `Zhuyin`、`English` 建立既有 `PredictionQuery`，沿用每個語言的預測器、
個人化排序與插件管線，再合併去重。拼音不參與自動語言判讀，避免把英文誤當拼音；
原有拼音模式保留。中文日期／計算機快捷碼另外走 `Chinese` 的插件管線。
候選足夠時保留中英文在第一頁的代表項，避免大量同音字或個人英文補全完全遮蔽另一語言。

`Candidate.input_mode`、`CandidateView.input_mode` 表示候選的實際語言解讀。
內部 `Selection` 同樣保存語言；完整上屏後分別記錄原有 `Zhuyin` 與 `English` 學習區，
跨語言片語不寫成單一混打編碼，接續詞關係仍可學習。舊版 JSON 資料無需遷移。
`CandidateSource::Literal` 表示可學習的英文原文，`Raw` 仍表示不可學習的保底內容。

`engine/mixed.rs` 負責混打按鍵與語言邊界：有完整聲調的中文前綴、已知英文詞／大寫縮寫
與帶聲調注音後綴可形成可退格復原的部分選字；完整上屏前不學習。
英文 Space 保留所打內容，補全由使用者明確選取；注音 Space 處理一聲或確認已完成聲調。
`KeyEvent::CommitRaw` 忽略部分選字，直接提交整段原始鍵碼且不學習，對應 GUI 的
Ctrl／Cmd+Enter、「保留原文」及 CLI `:raw`。

測試涵蓋原始鍵碼與雙語候選、連續雙向混打、大小寫／數字保留、歧義後綴、
分段退格、語言分區學習與重載、插件，以及真實 GUI 事件順序與淺深色／小視窗呈現。

## 10. 原生平台邊界

`senti-platform` 是平台無關的原生 host：直接包住 `InputEngine`，不持有 Demo 的文件，
透過版本化 JSON Lines 回傳是否攔截按鍵、上屏文字及 `EngineView`。
`EngineView` 與情境模型新增 serde 支援；既有預測器／儲存 ports 與 JSON 學習檔不變。

Linux Fcitx5 addon 位於 `platforms/linux/fcitx5`，以 C++ 呼叫 Fcitx 的 InputContext、
client preedit、CandidateList、設定與框架事件，再經私有 socketpair 呼叫 `senti-host`。
每個 addon 僅有一個引擎／模型 writer；活動欄位切換會取消前一欄位的未確認組字，
各欄位保留模式與本地候選 revision，拒絕過期 UI 點選。
未確認預編輯標記 DontCommit，避免框架在失焦時自行提交原始鍵碼。

原生 host 統一處理 Shift 單擊、快捷鍵放行、純注音／拼音／混打／英文方案、
敏感欄位隔離與周圍文字更新。周圍文字由平台以正確 OS 游標單位轉成 UTF-8 的 before-cursor 字串。
候選及上屏只套用到原請求欄位，不在前端自行學習或複製一份輸入引擎。

C++ 邊界有封包長度、版本、回應 id、逾時與子程序回收檢查；失敗不重播原請求，
放行原生鍵，必要時先保留目前可見預編輯內容。Linux 的程序／動態庫程式碼不進入 Rust 共用 crate，
因此不需放寬 workspace 的 Rust unsafe 禁令。

Windows TSF、macOS InputMethodKit 的接入規格分別在 `platforms/windows`、`platforms/macos`，
目前僅共用主程序／協定與資料目錄選擇，未實作或聲稱已驗證兩平台的原生套件。
詳細命令與生命週期契約見 [PLATFORM_PROTOCOL.md](PLATFORM_PROTOCOL.md)。

### 預選與確認式學習

`Predictor::suggest_context` 可使用有限的宿主前後文提出接續候選；目前 `NeuralPredictor` 以嵌入式神經權重提供中英文模型分數及高信心接續詞，舊規則擷取器已移除。
`CandidateSource::Context` 與一般鍵碼轉換分開，`EngineView.suggestion` 只傳送尚未接受的尾字串。
原生前端以 DontCommit 呈現該尾字串，維持真實游標位置；Tab 或候選選取才明確接受。
`view.selecting` 為候選窗唯一開關，按 Down 開啟；候選預計算與中文即時轉換可以在視窗隱藏時進行。

`UserModel.confirmed_words` 記錄明確選字，與一般自動提交頻率分開；保留 schema v1 並讓舊檔預設為空。
完整、帶聲調的詞庫詞語會受到排序保護，避免過去自動錯詞或短前綴的累積次數造成正回饋。
`Predictor::has_word_continuation` 讓原生窗口保留已知較長詞的輸入前綴，同時將局部替換限制在有限詞語內。

## 11. 產品方向與架構演進（2026-11-20）

本節記錄使用者確認的後續方向及可驗收的設計，不表示下列系統已經完成。
現有操作契約另保留在根目錄 `AGENTS.md`，後續開發需一併遵循。

### 現況診斷

以下為研究時的重構前診斷。逐次修補顯示、提交、局部切分與學習會形成互相依賴的行為：

| 現況 | 實際限制 | 對應改善 |
|---|---|---|
| `Mixed` 合併中英文候選，再靠多處分數與分支判斷語言 | 標點也是注音鍵，顯示政策可能意外變成提交或模式政策 | 建立單一解碼結果，分開判斷讀音、呈現及提交 |
| 注音 beam 每個位置保留六條路徑，最終只輸出一條組合句 | 正確路徑若先被剪掉，後續神經排序救不回來 | 提供保留語言與分詞差異的 N-best 詞圖候選，量測候選召回率 |
| v2 為固定六詞序列與十二詞主題的前饋網路 | 不等同前後文 Transformer，難以可靠解釋長距離語法 | 評估帶讀音條件的專用重排模型，英文補全另行評測 |
| `UserModel` 持久化詞頻、接續次數與確認次數 | 已有跨重啟詞頻，但沒有時間、拒絕訊號、專案或對話語境 | 建立具來源、時間與作用範圍的記憶事件與檢索 |
| 平台 `context` 代表暫時的輸入欄位，切換時清空周圍文字 | 不能把欄位 ID 當作跨天對話 ID，也不能把全域歷史直接當前文 | 分開欄位生命週期、應用程式識別、使用者指定的工作範圍與可選對話識別 |
| 每次學習可同步序列化 JSON、sync 與 rename | 資料成長時，可能拖慢真正的提交，現有 ephemeral benchmark 不涵蓋這段成本 | 記憶儲存移出按鍵熱路徑，測持久化提交及當機復原 |
| 小量固定回歸句與 sampled-token 指標 | 不能代表自然中文選字、混打或真人可用性 | 建立獨立語料、逐鍵重播與桌面驗收三層評測 |

### 參考 0c-IME 的分層方式

參考上游公開說明：先用詞圖、統計語言模型與搜尋產生候選，再以讀音及前文條件的
Transformer 重排，最後處理個人偏好；模型不可用時保留基本輸入能力。
這些是可借鏡的架構原則，不表示兩個產品目前具有相同效果。

- [0c-IME 原始庫與產品說明](https://github.com/0c-biggo/0c-ime)
- [選字技術與評測限制](https://0c.biggo.com/technology/)
- [公開 D512 候選重排模型與接入限制](https://huggingface.co/Funmula/0c-sequence-d512)
- [該固定模型版本的 MIT 授權](https://huggingface.co/Funmula/0c-sequence-d512/blob/d512-pf512-20260926/LICENSE)

可先將公開模型作為可選 adapter 做比較，不預設它一定勝過現有方案。
模型卡說明其候選來自特定字典，換成 Senti 的候選必須重新校準融合權重與門檻；
它需要外部候選，不能補救根本沒有召回的文字，也不是英文接續生成模型。
權重、範例、上游輸入法程式、字典與訓練資料各自核對授權與雜湊。
此段描述研究階段的設計。已實作的模型及執行方式如下方狀態。

### Senti 的差異化定位

以台灣注音使用者的連續中英輸入為中心，讓英文、注音、數字、標點與程式識別字自然共存。
AI 的工作是降低選字與修正成本；個人記憶的工作是保持用詞一致，不能接管使用者正在寫的內容。

| 能力 | 使用者應看到的行為 |
|---|---|
| 連續中英混打 | 未完成讀音顯示原始字母，混打優先完整合法讀音與詞庫支持的中文，包括一聲空白 |
| 穩定編輯 | 同一份解碼結果決定預覽、候選與 Enter；原始鍵碼可還原；明確選字是錨點 |
| 局部修正 | 後文可改善當前詞組，不會整段跳字；修正有範圍與可撤回資訊 |
| 可管理的個人記憶 | 跨天記得人名、專案術語與中英用詞，能查看、刪除、暫停或限定範圍 |
| 保守的接續補全 | 只有開始輸入後才提示，Tab 才接受；被忽略或刪除的建議不能當成偏好 |
| 中英工程情境 | URL、檔名、版本號、命令與程式識別字有保留原文測試，不被中文自動替換 |

0c 功能來源見 [上游 README](https://github.com/0c-biggo/0c-ime#-特色)。其台灣新聞評測與本專案的
UD Chinese-GSD 測例使用不同資料及候選流程，兩者分數不可直接比較。

本輪從 UD Chinese-GSD test 等距抽取 256 個相鄰二至四字的完整讀音片段。
`python scripts/evaluate_host_zhuyin.py <舊主程序> <新主程序>` 使用混打逐鍵組字，排除個人學習及外部模型。
記錄預覽後，按 Home、↓ 檢查文字起點的實際候選。最終版本與基準版本均為 150／256 首選命中，
156／256 預覽或第一頁命中。擴大詞圖寬度的試驗也只有 150 項首選命中，因此維持原先搜尋寬度。

### 同題逐鍵評測

新增中文字元二元／三元統計模型，使用 Chinese-GSD r2.15 train 統計並以 dev 決定融合權重。字元模型只為已有的讀音路徑打分，詞圖寬度仍為六。v2 仍重排完整路徑，D512 與 Qwen 的執行策略不變。

在 Chinese-GSD r2.15 test 依片段長度等距抽樣，每組 512 題。左側提供同一句中已知的最多 24 個字元，Senti 的兩版都關閉個人學習和外部模型。

| 片段長度 | 舊版首選 | 新版首選 | 舊版 → 新版字元編輯距離 |
| --- | ---: | ---: | ---: |
| 2–4 字 | 291／512 | 311／512 | 324 → 296 ／ 1,341 字 |
| 5–8 字 | 208／512 | 216／512 | 600 → 579 ／ 3,043 字 |

兩組評測的預覽與 Enter 都一致。另用 512 筆持久化記憶及 1,248 次按鍵／提交請求量測主程序往返，本機 p95 為 3.10 → 3.03 ms。

另以 [0c v0.2.13](https://github.com/0c-biggo/0c-ime/releases/tag/v0.2.13) 官方詞庫及引擎逐鍵重播同一批按鍵。
三方皆使用 0c v0.2.13 的選字權重，啟用混打並停用學習。每題從空白開始，無額外文件前文。
評測計入按鍵中途已提交或交還宿主的字元。0c 的模型狀態為 `ready`，Senti 維持原有工作期限與詞組範圍。

| 片段長度 | 舊版 Senti 首選 | 新版 Senti 首選 | 0c 首選 |
| --- | ---: | ---: | ---: |
| 2–4 字 | 275／512 | 286／512 | 335／512 |
| 5–8 字 | 189／512 | 196／512 | 304／512 |

延後壓縮組字到四音節的試驗使長片段開發集由 244 降至 234／512，也使「你好王曉鳴」已學姓名的測試失敗，因此未採用。
評測工具可用 `--without-context --d512 <模型目錄> --0c-socket <隔離測試 socket>` 重跑同題對照。
兩個尺寸範圍的結果只適用於唯一注音、沒有標點的中文片段。

游標中間的選字另用 `--following --min-length 1 --max-length 3 --cases 512` 評測。
將同一句的左、右文字交給原生主程序，只逐鍵輸入中間的注音，並關閉外部模型與個人學習。
加入右側字元模型分數後，首選從 371／512 升至 378／512，字元編輯距離從 174 降至 166（862 個參考字）。
兩版的預覽與 Enter 一致。這組測試量測既有文字之間的輸入，與上表的空組字比較分開報告。

### 建議的解碼與推論邊界

```text
原始按鍵與游標
  → 中英／注音／標點的增量詞圖
  → 有界 N-best 解碼（含原文保底、手選錨點、每段原始鍵碼範圍）
  → 統一 DecodeResult
       ├─ 立即呈現與基本候選
       └─ 非同步重排請求：組字 revision + 欄位世代 + 上下文 + 受限記憶
            → 校準後的信心與改善幅度
            → 僅在 revision／欄位仍相符、游標與錨點未變時更新當前詞組
  → Enter 提交同一結果；Tab 接受預選；提交後發出記憶事件
```

`DecodeResult` 應攜帶 raw span、呈現文字、語言、音節完成狀態、候選來源與確認狀態。
不要在 UI、Enter 與前段壓縮時各自重算一個可能不同的第一候選。
先保持現有六字修改上限，再用詞邊界取代硬切；不可為了模型長上下文而擴大修改範圍。

推論服務需有有界佇列、取消舊請求、模型版本、快取鍵、逾時與降級。
已上屏文字、失焦欄位及手動選定的範圍不能被遲到的結果覆寫。
信心需在開發資料校準；模型 softmax 或分數差不直接等於正確率。

### 跨對話記憶：資料與作用範圍

使用者已確認同時需要輸入法長期記憶及開發需求延續。
輸入法的記憶設計分成四種，不能只把所有舊句子串成模型前文：

1. **游標上下文**：宿主目前提供的前後文，最高優先，只用於當下判斷。
2. **對話／工作範圍**：同一工作或對話的已提交片段與近期術語，可跨重啟恢復。
3. **個人偏好**：明確選字、改正配對、人名、術語與接受的補全，長期保留並允許衰減與刪除。
4. **專案知識**：使用者明確加入的詞彙或片語，按專案或自選 profile 生效。

對話片段保留需有設定、容量與保存期限；使用者可啟用、暫停及清除。
只從本輸入法可取得並允許保存的輸入建立記憶，不宣稱能取得其他參與者的訊息或完整聊天歷史。
在敏感欄位與暫停記憶狀態，不保存或檢索對話內容。
查詢帶範圍、語言、時間、詞語／讀音等條件，只取少量相關記憶；記憶優先級低於明確輸入和手選。

平台可提供可靠的對話識別時才使用；Fcitx 的暫時 InputContext ID 不能冒充對話識別。
沒有可靠識別時，使用者可選工作 profile；應用程式識別只支援偏好分區，不能自動混合所有聊天全文。
這是 Linux 桌面能力邊界，需要在 UI 清楚呈現實際可保存的範圍。

持久化可用 SQLite 交易及 WAL，將事件寫入與索引更新移出按鍵路徑；儲存 adapter 維持可替換。
事件至少包含：種類、作用範圍、語言、鍵碼／文字配對、來源、時間、接受／改正／撤回狀態。
自動首選、明確選字、Tab 接受、單純忽略與刪除是不同訊號，不能全部加正向詞頻。
短暫刪除不直接當成強烈拒絕，需有可對應的修正配對，避免誤學一般編輯行為。
舊 JSON 詞庫需備份、可重入匯入並保留回退；舊的自動錯詞不能升級成可信的已確認記憶。

### 實作順序與驗收

| 階段 | 交付內容 | 完成條件 |
|---|---|---|
| P0 穩定輸入 | 統一 DecodeResult、逐鍵重播、輸入契約測試 | 主要入口逐鍵預覽與 Enter 一致；混打、句點、空白、退格、插入及手選不互相破壞 |
| P1 記憶基礎 | 帶範圍事件、儲存遷移、查看／刪除／暫停、修正訊號 | 重啟後同 profile 能使用已確認用詞；其他 profile 不被污染；清除後不再召回；當機不損壞詞庫 |
| P2 候選與模型 | N-best 介面、候選召回量測、可替換非同步重排、校準 | 在凍結的相同測試集優於基線；過期結果不套用；慢模型不阻塞基本按鍵 |
| P3 個人化體驗 | 中英補全、記憶檢索與 UI、台灣用語校準 | 實際降低選字與修正按鍵；沒有組字不提示；忽略與撤回不被錯學；清楚顯示記憶來源 |

獨立測試至少分為日常聊天、台灣生活、工作／技術、的得地／同音字、錯序與重複鍵、
中英數字符號、局部編輯、舊學習污染及跨天／跨應用記憶。訓練模板與回歸句不能混進獨立測試。
報告字錯率、詞語／整句首選正確率、N-best 正解召回率、每百字人工選字／修正次數、
已正確前文被改壞的比率、補全接受／撤回率，以及真實持久化下的按鍵與提交 p50/p95/p99。
數值門檻在凍結驗收集前設定；上游公開成績不能當作 Senti 的成績或直接跨資料集比較。

### 已落地的第一批改造（2026-11-21）

- P0：新增 `DecodeResult`／`DecodeSegment`，保存 revision、原始範圍、文字、模式、來源、完成與確認狀態。混打顯示、Enter、Ctrl+標點與原生前段切分共用這份快照；明確選字與 Tab 仍是獨立的使用者操作。純拼音等既有方案保留原本的確認規則。
- P0：`testdata/input-contracts.json` 與 `scripts/replay_input.py` 重播真實主程序，檢查逐鍵預覽、提交一致性、原文還原、編輯、空白、標點、URL、檔名與版本號。這是操作契約回歸，不是自然語料正確率。
- P1：新增獨立 `MemoryStore` port 與 `personal_memory.json`。舊 `user_model.json` 沿用，不匯入為可信的明確選字事件。新增資料有範圍、時間、接受次數及來源，區分提交脈絡、明確選字、接受補全、已提交的編輯修正。
- P1：記憶最多 512 筆，其中提交脈絡最多 128 筆、每筆最多 256 字；預設保存 30 天，可調整。啟動與寫入時清理過期內容；重新啟動後可沿用同一範圍的詞彙與相關脈絡。
- P1：使用背景合併快照、原子 rename 與明確 flush；正常 EOF 關閉會排空待寫資料。Unix 新檔權限 0600。損壞記憶保留原檔並停用該記憶寫入，輸入引擎仍可運作。突發斷電仍可能失去最後一筆尚未落盤的快照。
- P1：Linux 設定與狀態選單可暫停、指定範圍、調整保存天數、查看及刪除記憶；Demo 設定也有記憶管理。管理走原本的主程序，維持單一 writer。

預設 Linux `app:<program>` 只保存應用程式用詞，不把不同聊天對象的全文自動拼接。設定自訂工作範圍後才保存自己提交的脈絡；工作範圍由使用者決定，不假裝等同聊天軟體的對話 ID。只有同範圍、有相關詞串的少量脈絡會用於排序；目前是保守的詞串檢索，尚未提供語意向量檢索。

自動提交不是明確偏好。未確認組字、忽略的補全及取消的編輯不產生可信修正；補全記憶還需符合原先的前文。新記憶的罕見自訂詞須重複明確接受，才可能取得完整詞排序保護。清除範圍記憶保留舊詞庫；重置全部個人化資料會一併清空新記憶。

本版使用有界 JSON 快照儲存；`MemoryStore` 可替換為 SQLite，未加入 SQLite 依賴。P2 可選配 0c D512 與 Qwen3-0.6B。左側語境優先由 D512 重排，具有右側語境時可由 Qwen 評分。Fcitx5 以組字 revision、欄位及前後文檢查延遲結果。完整品質評測、候選召回率與更深入個人化仍待實作。
