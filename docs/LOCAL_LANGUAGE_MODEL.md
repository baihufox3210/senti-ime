# 本機中英文神經模型與自動選字

現在預設使用實際訓練的雙語小型神經模型，搭配注音詞庫與 beam search。
舊的停用詞表、猜名詞、單複數字尾規則已移除；不是把規則重新命名為 AI。
權重約 7.1 MB，直接嵌入 Rust 主程序，以 CPU 推論，不上傳輸入內容。

模型架構、來源授權、重訓指令及完整驗證結果見 [模型說明](../models/tiny-ime-v2/README.md)。
這是小型神經模型基線，不具備大型 LLM 的完整語意能力。低信心時不提供接續建議；
它不保證所有同音多義字或任意句子都能猜中，也不保證提過 apple 就一定接出 apples。

## 中文選字

- 完整、帶聲調的詞庫詞優先於沒有詞庫依據的拆字組合。
- 注音學習候選必須符合對應音節的中文字數與文字類型，排除 `並且` 的注音卻帶出 `btw` 等污染資料。
- 舊自動錯詞與誤確認詞不會只憑累積次數蓋過完整詞庫詞；仍可手動選取自訂詞，詞庫內的個人化同音詞仍可學習。
- 未經手動確認的中文前段可隨後文重新解碼，不再因分詞提早固定而一直保留錯字。
- 手動確認的字詞維持固定；回頭改詞仍限定在游標附近的詞組，不改寫已上屏文件。
  游標中間輸入完整注音時，自動選字與候選窗同樣使用右側組字及宿主提供的後文。
  修正候選以游標開始的目前單詞為範圍，例如「然後修正」中選「然後」時只替換「然後」。
  例如在「土」前插入 `su6`，自動選成「泥土」。中文神經排序以緊鄰的字為主，並參考右側最多四個 token。
  編輯模式輸入下一個完整音節後，會重排結尾的一個詞，例如把暫時顯示的「字」補成「自己」，手選字是修正邊界。
- 支援音節內一次相鄰注音鍵換位或重複鍵。混打遇到無法解析的尾端，例如 `su3cl3qzz`，保留已顯示的「你好」與待編輯的 `qzz`。Ctrl+Enter 可還原鍵碼。
- 程度詞後可用詞頻證據修正兩字詞的一處聲調，例如「不夠知會」轉為「不夠智慧」。自動修正不寫成原讀音的詞庫偏好。
- 詞庫維持 80,104 個詞語、21,694 個單字；所有附帶單字仍可在原生候選預算內選取。

回歸測試包括高次數、已確認的舊錯詞「解少／病且／字動」與跨語言 `btw` 污染，
以及「介紹一下你自己並且自動選字」的連續組字、手動錨點、原文還原與英文保留。
詞庫命中與上述測試通過，不等於全中文語意正確率。

注音詞圖產生候選後，由本機神經模型對完整路徑重排。最多保留四條完整路徑供選字，次選不享有首選的詞庫排序保護。
「呢」的輕聲鍵是 `7`，混打可輸入 `ji3sk7`（我呢）。最後一個音節若輸入一聲或二聲，沒有完整的精確匹配時，才嘗試詞庫中的輕聲語氣詞。

## 完成組字後的刪除

混打與注音模式中，完整組字按 Backspace 會刪除一個顯示中的中文字與其對應鍵碼，
例如「資料集 → 資料 → 資」；尚未完成的注音及英文仍逐鍵刪除。
手動選字後也採相同規則；已上屏文字由應用程式處理退格。

## 預選與候選窗

英文接續詞來自神經模型機率及學到的語法訊號，不產生人工加 s 的 `eats` 推薦。
高信心預選以斜體尾字串顯示。混打輸入至少三個英文字元時，若仍是未完成單字，可用詞庫和模型詞彙表補全，例如 `tomo` 顯示 `rrow`。Tab 或候選選取才接受，Enter 提交原輸入。
中文自動選字也使用神經分數；沒有組字時不顯示接續預選，避免憑空出現 `is` 等文字。
候選窗維持按 ↓ 才出現，Esc 關閉；游標在已轉換中文字末尾時，按 ↓ 會聚焦最後一字。Shift+Tab 保留焦點移動。

預選尾字串帶 DontCommit，不會在失焦或背景程序故障時被當成已輸入文字提交。
密碼、敏感與數字欄位不進入模型。

## 執行與效能

模型只初始化一次。推論與詞庫快取有上限，原生 UI 每筆按鍵只發布一次完整組字。
自動前段重解碼使用最近至多 24 個音節作為判斷上下文，只改動尾端六個字，保留較早文字、明確選字與原始鍵碼；不對整份文件做全文重寫。
可執行：

```sh
python scripts/benchmark_native.py
python scripts/benchmark_native.py --scenario context
```

這些只測本機主程序與 JSON IPC，不含桌面繪製或真實應用程式的端對端延遲。

## 連續輸入與學習資料

切分自動組字時，前段文字取自完整解碼路徑，保留後文對「完／玩」的判斷，
避免重新單獨選字時讓舊單字學習紀錄蓋回錯字。注音解碼快取區分完整前文，
不再將最後一字相同的不同語境視為同一筆結果。這些修正不清空個人學習資料。

預設以中英混打啟動並顯示「中英」；Shift 可切換純英文後再切回。輸入中的英文仍可提供 AI 接續建議，
空組字、提交後、退格清空後都不顯示預選。

混打模式預設顯示原始字母：`s → su → 你 → 你c → 你cl → 你好`。
完成合法注音音節（包含聲調鍵；一聲用空白）才轉換成中文；未完成或無字可選時保留原文。
混打的注音解讀提示只在開啟候選時提供；純注音入口仍保留注音顯示。

混打模式的 Enter 保留未完成的注音鍵碼，不替缺少聲調的尾段選字。
例如 `. + Enter → .`、`su3. + Enter → 你.`；輸入完整 `g.3` 仍可轉換成「手」。
混打預設半形標點，例如 `你好!`。Ctrl+`.` 輸入全形句號「。」，Ctrl+Shift 搭配問號鍵輸入「？」。

## 統一解碼與操作重播

混打預覽、Enter 與原生前段切分共用 `DecodeResult`，提交時不再重新挑第一候選。
每段保留原始鍵碼範圍、語言、來源、完成與確認狀態；候選點選與 Tab 是明確的覆寫操作。
`v1.2` 等版本號保留原文，計算機仍支援 `v1+2` 與 `v(1+2)*3`。

```sh
python scripts/replay_input.py
python scripts/benchmark_native.py --persistent --memory-entries 512
```

重播是人工撰寫的操作回歸，涵蓋 23 組案例；不代表所有中文場景或獨立語言評測。
帶 `--persistent` 的基準使用暫存資料夾，包含提交與真實背景存檔，不讀寫個人資料；仍不含桌面繪製。

## 跨天的個人記憶

在 Fcitx 的 SentiIME 設定可控制 Memory、MemoryProfile、MemoryDays。
MemoryProfile 留白時依應用程式分開保存已確認用詞；設定例如 `work:atlas` 才保存自己提交的對話脈絡。
同一範圍可跨對話與重啟沿用。這不是聊天軟體的完整歷史，也不會讀取其他人的訊息。
輸入法狀態選單的「個人記憶」可查看及刪除條目，或清除目前範圍；Demo 的設定中也有記憶管理。

新檔 `personal_memory.json` 與 `user_model.json` 同目錄。預設保留 30 天，最多 512 筆，其中提交脈絡最多 128 筆。
來源區分自動提交、明確選字、接受補全及已提交的修正；忽略建議、未送出選字及取消編輯不會記成偏好。
補全記憶必須符合前文，相關舊脈絡以詞串檢索，優先度低於當前上下文與手選。
暫停時不自動檢索或新增記憶，管理功能仍可使用；密碼與敏感欄位也禁止查看或修改記憶。
清除目前範圍不刪除舊詞庫；重置全部個人化資料會同時清除新記憶。

記憶檔背景寫入，正常關閉會排空待寫資料；原子替換保護已有快照。
異常終止仍可能失去最後尚未落盤的更新。損壞檔案會保留並停用記憶寫入，不會以空檔覆蓋。
即時解碼由 v2 提供基線。已安裝 0c D512 權重時，完整注音詞可由本機 Transformer 自動重排。語意向量檢索仍待實作。


混打遇到英文詞與注音一聲空白重疊時，若詞庫支持該讀音和後續詞組，先顯示中文並保留鍵碼。`up + Space` 顯示「因」，Enter 直接提交。同一組字可繼續輸入 `jo4` 轉成「因為」。接上詞庫認得的英文詞時，`up there` 仍可提交英文。不明尾碼保留原樣，原始鍵碼可用 Ctrl+Enter 提交。

輸入中的英文補全會使用游標前文與可用的工作範圍記憶。「any」出現在可接名詞的語境時，可查找前文提過的可數名詞。詞性證據取自本機模型與英文語料；候選以模型分數與最近出現的位置排序。自訂 MemoryProfile 可跨重啟使用自己的提交脈絡。預選出現時按 Tab 接受。


混打中的單獨 `up` 按 ↓ 會使用一聲讀音列出「因、音」等候選，接續完整讀音 `up jo4` 則轉成「因為」。有舊英文學習紀錄時，`u uv, ` 的最後空白在詞庫確認完整讀音後仍是一聲，轉成「一些」。未補最後空白時，可用 ↓ 選擇詞庫候選。

擴大後的 v3 及同音字比較收錄在 [v3 研究模型](../models/tiny-ime-v3/README.md)。本次預設版使用通過既有回歸的 v2。

## 受限候選的模型比較

從 UD Chinese-GSD test 檔挑出前一字和目標字都有唯一注音、且各模型共享字表的例子。
依詞頻取至多 16 個同音候選，共有 1,137 題的正解在候選內。
0c 的輸入是兩音節，固定第一個字，再對第二個字評分。v2 與 v3 把同一個已知字放在前文末尾。
同一批題目的詞頻首選是 51.63%。

| 模型 | 純模型首選正確率 |
| --- | ---: |
| v2 | 75.73% |
| v3 | 74.93% |
| 0c D512 Q4 | 84.87% |

0c 使用官方量化權重，在 Ryzen 5 7500F 上以 ONNX Runtime、2 條執行緒評分。
先在其中 256 題確認共用前綴的批次評分與逐候選評分結果相符，再對完整 1,137 題測量批次速度。
整組候選評分的 p50 是 4.33 ms，p95 是 8.34 ms。這適用於本測試中只有最後一字不同的候選。本測試只量候選內排名和評分時間。
詞庫召回、一般多詞候選的速度與原生桌面延遲需另測。外部模型的訓練語料未完整公開，無法排除與測試集重疊。Fcitx5 以 v2 提供即時基線，可搭配已安裝的 D512 重排。

另以 UD Chinese-GSD train 的 512 題來校準 0c 分數與詞頻的加權，測試集首選正確率為 84.78%。
本次保留純模型成績作為比較基準。Qwen3-0.6B 的權重與 CUDA 依賴下載未完成，沒有 LoRA 實測結果。

把官方的 Q4 `model.onnx`、`model.onnx.data` 與 `vocab.json` 放到同一個目錄。在有 NumPy、
ONNX Runtime 及既有訓練語料的環境執行下列指令。

```sh
OPENBLAS_NUM_THREADS=2 python scripts/evaluate_zhuyin_homophones.py \
  models/tiny-ime-v2 models/tiny-ime-v3 --d512 /path/to/d512-q4 --sample-size 1137
```

公開權重與量化限制見 [0c D512 模型卡](https://huggingface.co/Funmula/0c-sequence-d512)。
Qwen 權重與授權見 [Qwen3-0.6B 模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)。


## 本機 Transformer 自動修正

完整的兩到六音節詞組會送出最多六個同讀音候選，讓 D512 以最多 64 字的左側語境評分。
組字編輯中的既有自動結果也可參加比較。右側文字由本機語言模型評分，手選內容是修正邊界。
一次只重排目前詞組，Enter 沿用同一份預覽。所有推論都在本機，候選仍由輸入法詞圖提供。

Linux 安裝可在 CMake 設定時指定 `SENTI_D512_DIRECTORY`。該目錄須包含官方 Q4 的
`model.onnx`、`model.onnx.data`、`vocab.json`、`LICENSE`。Python 3 需可載入 NumPy 和 ONNX Runtime，
也可把相容版本安裝到模型目錄的 `python/`。主程序會自動載入隨安裝附帶的 `d512/`。
可用 `SENTI_IME_D512_MODEL` 或個人資料目錄下的 `d512/` 指定模型。
權重載入在獨立程序中進行。D512 忙碌、未就緒或超過當次按鍵剩餘的模型等待預算時使用 v2。


### Qwen3-0.6B 的前後文評分

Linux 混打有右側文字時，優先用官方 Qwen3-0.6B Q8_0 評分。模型從左側文字續讀候選詞及右側前三個 token，
比較條件機率。待選內容由輸入法提供，模型只回傳分數。沒有右側文字時，仍優先使用帶注音條件的 D512。
兩個模型共用每鍵最多 15 ms 的等待預算，Qwen 最多等待 5 ms。較慢的 Qwen 結果可在 250 ms 之內更新仍顯示的
同一版普通組字，選字、提交、失焦或原始按鍵／前後文改變時捨棄。游標編輯組字只採用即時結果。

以相同的 256 筆 UD Chinese-GSD test 同音候選比較，最多六個候選，先前字固定且正解已召回：

| 模型 | 候選首選正確率 | 單組模型評分 p95 |
| --- | ---: | ---: |
| 0c D512 Q4 | 83.98% | 8.49 ms |
| Qwen3-0.6B Q8_0 | 76.56% | 12.93 ms |
| 內建 v2 | 75.39% | — |

Qwen 使用 RTX 3070 Vulkan，D512 使用 CPU。比較只提供左側語境，兩者數字均為相同候選集合內的排名，
整句選字、真實按鍵延遲與 Fcitx5 桌面驗收應分別看待。Qwen 使用官方預訓練權重。
使用 `python scripts/benchmark_native.py --scenario rerank --iterations 48` 進行 360 次主程序 IPC 往返。
在本機硬體上啟用 Qwen 與 D512 後，按鍵與提交的 p95 為 6.97 ms，較慢的模型改選在重播中位數約 20.2 ms 可見。
四個固定的前後文案例各通過 12 次，另以實際 Fcitx5 addon 和暫存安裝包驗證「他是一位優秀的經紀，代理過許多藝人」。


用匹配版的 llama.cpp 標頭與共享函式庫建置 `senti-qwen`。本次使用 b12606。CMake 的
`SENTI_QWEN_DIRECTORY` 指向含 `include/`、`model.gguf`、`QWEN-LICENSE`、`LLAMA-LICENSE` 的目錄，
`SENTI_LLAMA_LIBRARY_DIR` 指向匹配的共享函式庫。安裝會自動佈署模型、兩份授權及執行程式。
開發模式可將 `SENTI_IME_QWEN_MODEL` 指向含 `senti-qwen`、`model.gguf`、`lib/` 的目錄。
無可用模型時可正常使用其餘選字管線。
